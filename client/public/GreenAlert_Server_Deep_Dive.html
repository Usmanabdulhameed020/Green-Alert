1. server.js Entry Point

server/src/server.js

This is the very first file that runs when you type npm start. It boots the entire application.

require('dotenv').config()

Loads all environment variables from your .env file into process.env. This MUST be the first line so that every other file can access secrets like MONGODB_URI, JWT_SECRET, GEMINI_API_KEY, etc.

require('./config/env')

Runs the envalid validation module. It checks that every required environment variable exists and has the correct type. If MONGODB_URI or JWT_SECRET is missing, the server will crash immediately with a clear error instead of failing silently later.

const server = http.createServer(app)

Creates a raw Node.js HTTP server wrapping the Express app. Why not just app.listen()? Because Socket.IO needs a raw HTTP server reference to attach WebSockets. Express's built-in app.listen() hides the server object, so we create it manually.

new Server(server, { cors: {...} })

Initializes Socket.IO on top of the same HTTP server. The cors option allows the React frontend (running on localhost:5173 or your Vercel URL) to establish WebSocket connections. Without this, the browser would block the connection.

initSocket(io)

Passes the Socket.IO instance to socket.service.js which sets up event listeners for join-user, join-agency, join-admin, etc. This enables real-time notifications.

startServer() — async function

The boot sequence:

1️⃣ await connectDB() — Connects to MongoDB Atlas. If this fails, the server crashes (no point running without a database).
2️⃣ await seedAdmin() — Checks if an admin account exists. If not, creates one using ADMIN_EMAIL and ADMIN_PASSWORD from .env.
3️⃣ server.listen(PORT) — Starts accepting HTTP requests on port 5000.

shutdown(signal) — Graceful Shutdown Handler

Listens for SIGINT (Ctrl+C) and SIGTERM (server kill signal). When received:

1️⃣ Stops accepting new HTTP connections.
2️⃣ Disconnects from MongoDB cleanly (prevents data corruption).
3️⃣ Force-kills the process after 10 seconds if graceful shutdown hangs.

2. app.js Express Pipeline

server/src/app.js

This file creates the Express application and wires up ALL middleware and ALL routes. Think of it as the "wiring diagram" of the entire backend.

Rate Limiting — app.use('/api', apiLimiter)

Limits every client to 100 requests per 15 minutes across all API endpoints. Prevents brute-force attacks and abuse.

authLimiter is stricter — applied specifically to /login and /register (20 requests per 15 min in production) to prevent password brute-force.

Service Initialization (Lines 40–47)

• cloudinaryConfig.configureCloudinary() — Connects to Cloudinary for image/video uploads.
• brevoConfig.configureBrevo() — Initializes the Brevo (Sendinblue) email API client.
• pushConfig.configurePush() — Validates VAPID keys for browser push notifications.
• geminiConfig.configureGemini() — Runs in background; queries Google's API to discover the best available AI model (prefers gemini-2.0-flash).

CORS — Cross-Origin Resource Sharing (Lines 50–68)

What it does: Controls which websites are allowed to call your backend API.

• Any localhost or 127.0.0.1 origin is allowed (for development).
• Your Vercel production URL (https://greenalert001.vercel.app) is whitelisted.
• credentials: true allows cookies (JWT tokens) to be sent cross-origin.
• Any other origin gets rejected with "Not allowed by CORS".

Body Parsers — express.json() & express.urlencoded()

express.json() parses incoming JSON request bodies (e.g., when the frontend sends { title: "Blocked drain", ... }).

express.urlencoded({ extended: true }) parses HTML form submissions.

Security Middleware

• helmet() — Adds 15+ security HTTP headers: X-Frame-Options (prevents clickjacking), X-Content-Type-Options (prevents MIME sniffing), Content-Security-Policy, etc.
• sanitize — Custom middleware that strips any MongoDB injection operators ($gt, $ne, etc.) from request bodies. Without this, an attacker could send { "email": { "$gt": "" } } to bypass login checks.
• compression() — Gzip-compresses all HTTP responses, reducing payload size by ~70%.

Morgan — HTTP Request Logger (Lines 79–81)

Logs every incoming HTTP request in Apache Combined format. Pipes output through Winston logger so requests appear in both console and log files.

Swagger API Documentation (Lines 87–90)

Serves interactive API documentation at /api/docs. Auto-generated from JSDoc comments in route files.

Route Registration (Lines 92–127)

Every route is registered on BOTH /api/ and /api/v1/ for reliability (some frontend components use different prefixes).

15 route groups are registered:
auth • auth (google) • health • reports • notifications • upload • communities • posts • replies • polls • admin • agency • push • system • chat

3. Config Files Configuration

config/database.js

Handles MongoDB Atlas connection with custom timeout settings.

connectDB()

Connects to MongoDB using MONGODB_URI from .env. Uses 3 timeout values: serverSelectionTimeoutMS: 45000 (wait up to 45s to find a server), connectTimeoutMS: 30000, socketTimeoutMS: 45000. These generous timeouts handle slow cold-starts on free-tier Atlas clusters.

getStatus()

Returns human-readable connection state: "connected", "disconnected", "connecting", or "disconnecting". Used by the health check endpoint.

config/env.js

Environment variable validation using the envalid library.

envalid.cleanEnv(process.env, schema)

Validates every .env variable at startup. Required vars: MONGODB_URI, JWT_SECRET. Optional with defaults: PORT (5000), JWT_EXPIRES_IN (700d), BCRYPT_SALT_ROUNDS (12), all Cloudinary/Brevo/VAPID keys (default empty string). If a required variable is missing, the process exits with code 1 and a clear error message.

config/adminSeed.js

Auto-creates the platform administrator account on first server boot.

seedAdmin()

Boot-time logic:

1️⃣ Reads ADMIN_EMAIL and ADMIN_PASSWORD from .env.
2️⃣ If they're empty, skips seeding (no admin created).
3️⃣ Checks if a user with that email already exists.
4️⃣ If user exists but isn't an admin → promotes to admin role.
5️⃣ If password changed in .env → updates the password hash.
6️⃣ If no user exists → creates a new admin account with role: 'admin' and isVerified: true.

config/gemini.js

Configures Google Generative AI (Gemini) and dynamically resolves the best available model.

configureGemini()

At startup, queries https://generativelanguage.googleapis.com/v1beta/models to list all models available for your API key. Filters for models supporting generateContent. Picks the best one in priority order: gemini-2.0-flash → gemini-1.5-flash → gemini-1.5-pro. Skips deprecated gemini-2.5-flash. Stores the chosen model name in activeModelName.

getGenAIInstance() / getActiveModelName() / checkStatus()

Helper functions to retrieve the AI client, the resolved model name, and connectivity status (used by health check).

config/achievements.js

Defines the gamification achievement ladder.

8 Achievement Definitions

Report-based: First Report Alert (1), Active Sentinel (5), Community Guardian (10), Eco Champion (25).
Resolution-based: Problem Solver (1 resolved), Impact Maker (5 resolved).
XP-based: Eco Hero Badge (200 XP), GreenAlert Legend (500 XP).

4. Mongoose Models Database Schema

models/User.js

Defines the schema for every user account in the system (citizens, agencies, and admins).

Schema Fields (18 fields)

fullName (required, trimmed) • email (required, unique, lowercase) • phone (optional) • password (required, min 6 chars, select: false — never returned in queries unless explicitly requested) • role (enum: citizen/agency/admin, default: citizen) • isVerified (boolean) • avatar (Cloudinary URL) • organizationId (ObjectId ref to Organization) • passwordChangeCode + passwordChangeCodeExpires (for forgot-password flow) • emailVerificationCode + emailVerificationCodeExpires • status (active/banned) • banReason + bannedAt + bannedBy • xp (gamification points, default 120) • unlockedAchievements (array of achievement IDs) • settings (embedded notification/privacy preferences)

pre('save') Hook — Password Hashing

Runs before every save. If the password field was modified, it hashes it using bcrypt with the salt rounds from BCRYPT_SALT_ROUNDS .env (default 12). This means plain-text passwords are NEVER stored in the database.

comparePassword(candidatePassword)

Instance method. Takes a plain-text password candidate, hashes it with the same salt, and compares against the stored hash. Returns true if they match. Used during login.

models/Report.js

The core data model — represents a single environmental incident report.

Schema Fields (20+ fields)

title • description • location (text address) • latitude / longitude (GPS coords) • category (Illegal Dumping, Blocked Drainage, etc.) • status (enum: Submitted → Under Review → Assigned → In Progress → Resolved → Closed) • priority (Low/Medium/High/Critical) • user (ref to User who created it) • assignedTo (ref to Organization) • imageUrl + images[] (Cloudinary URLs) • aiCategory / aiSummary / aiSeverity / aiDuplicateOf / aiSuggestedOrg / aiAnalyzed (AI analysis results) • comments[] (embedded subdocuments with nested replies) • resolutionImages[] + resolutionNotes (agency proof) • resolvedAt (timestamp)

Embedded Comment & Reply Schemas

commentSchema has fields: user (ref), text (max 2000 chars), replies[] (array of replySchema). replySchema has: user (ref), text. Both have timestamps: true. This means comments are stored inside the Report document (embedded), not in a separate collection.

models/Organization.js

Represents a responding agency/organization that handles environmental reports.

Schema Fields

name (unique) • description • email • phone • address • website • category (enum: Waste Management, Drainage & Flood Control, Oil & Chemical Spill Response, Air Quality Management, Water Treatment, Parks & Forestry, Roads & Infrastructure, Multi-Purpose) • licenseNumber + licenseDocument (uploaded PDF) • verified (boolean — must be approved by admin) • status (Active/Inactive/Suspended) • user (ref to the agency's User account)

models/Settings.js

Singleton document for platform-wide admin settings.

Fields

maintenanceMode (boolean) • maintenanceMessage (string) • announcementEnabled (boolean) • announcementMessage (string). The getSettings() helper finds the single settings document or creates one with defaults if none exists.

5. Middlewares Security Layer

middlewares/auth.middleware.js

Protects routes and enforces role-based access control.

protect(req, res, next)

The gatekeeper. Runs before every protected route. Steps:

1️⃣ Extracts JWT token from cookies (req.cookies.token) OR from Authorization header (Bearer xxx).
2️⃣ If no token → returns 401 "You are not logged in".
3️⃣ Verifies the token signature using JWT_SECRET. If tampered or expired → 401.
4️⃣ Loads the full User document from MongoDB using the decoded user ID.
5️⃣ If user no longer exists → 401 "user does no longer exist".
6️⃣ If user status is "banned" → 403 "Account suspended".
7️⃣ If maintenance mode is ON and user is NOT admin → 503 "Under maintenance".
8️⃣ Attaches user to req.user and calls next().

authorize(...roles)

Returns a middleware that checks if req.user.role is in the allowed roles array. Example: authorize('admin') blocks citizens and agencies. Returns 403 if unauthorized.

middlewares/rateLimit.middleware.js

Prevents API abuse using express-rate-limit.

apiLimiter / authLimiter

apiLimiter: 100 requests per 15 minutes for all API routes. authLimiter: 20 requests per 15 minutes for login/register (production only). Local development is exempt — the skip function detects localhost/127.0.0.1 and bypasses limits.

middlewares/sanitize.middleware.js

Prevents NoSQL injection attacks on MongoDB.

sanitizeValue(obj)

Recursively walks through every key in req.body. Deletes any key starting with $ (MongoDB operators like $gt, $ne, $regex) or containing . (dot notation attacks). Without this, an attacker could send {"password": {"$gt": ""}} to bypass authentication.

6. Services Business Logic Layer

services/ai.service.js

Reusable Gemini AI text generation with automatic multi-model failover.

generateText(prompt)

The AI engine. Creates a unique model fallback chain: [dynamically resolved model] → gemini-2.0-flash → gemini-1.5-flash → gemini-1.5-pro → gemini-pro. Tries each model in sequence. If one is rate-limited or errors, it silently moves to the next. Only throws an error if ALL models fail. This ensures maximum AI availability.

services/socket.service.js

Socket.IO real-time WebSocket event management.

initSocket(io) — Room-based Architecture

When a client connects, they join specific "rooms" based on their role:

• join-user → joins user:{userId} room (for personal notifications).
• join-agency → joins agency:{orgId} room (for agency-specific alerts).
• join-admin → joins admins room (for system-wide admin alerts).
• join-report → joins report:{reportId} room (for live comments/replies).
Also handles typing indicators with auto-timeout after 3 seconds of inactivity.

Emit Functions (6 event emitters)

• emitReportAssigned(report) → sends to agency room + admins room + citizen room.
• emitReportStatusChanged(report) → sends to citizen + agency + admins.
• emitNewReport(report) → sends to admins only.
• emitReportComment(reportId, comment) → sends to everyone viewing that report.
• emitReportReply(reportId, commentId, reply) → same as above.
• emitNotification(notification) → sends to the specific user's room.

services/push.service.js

Free browser push notifications via Web Push API (VAPID protocol). No paid service needed.

sendPushToUser(userId, title, body, url)

How it works:

1️⃣ Queries PushSubscription collection for all active subscriptions belonging to this user (one per device/browser).
2️⃣ Configures VAPID credentials using VAPID_PUBLIC_KEY and VAPID_PRIVATE_KEY from .env.
3️⃣ Encrypts the notification payload (title, body, icon, URL).
4️⃣ Sends to each subscription endpoint via web-push.sendNotification().
5️⃣ If a subscription returns 410 (Gone) or 404, it's expired → auto-deletes from DB.
6️⃣ Returns the count of successful deliveries.

sendPushToAdmins(title, body, url)

Finds all users with role: 'admin' and calls sendPushToUser() for each one.

services/gamification.service.js

XP rewards and achievement unlock engine.

awardXP(userId, amount)

Adds amount XP to the user's xp field. Then calls checkAndUnlockAchievements() to see if they've earned any new badges.

checkAndUnlockAchievements(user)

Counts the user's total reports and resolved reports from MongoDB. Then loops through all 8 achievements and checks if the user meets each requirement. Newly unlocked achievement IDs are pushed to user.unlockedAchievements[] and saved.

7. auth.controller.js Authentication

controllers/auth.controller.js (578 lines)

Handles ALL authentication: register, login, logout, password reset, email verification, profile management, achievements, and leaderboard.

signToken(user) → JWT Token Creation

Creates a JWT containing { id, email, role }. Signed with JWT_SECRET. Expires after JWT_EXPIRES_IN (default 700 days). This token is the user's "session key".

createSendToken(user, statusCode, res, message)

Helper that: 1️⃣ Signs a JWT, 2️⃣ Sets it as an HTTP-only cookie (prevents XSS theft), 3️⃣ Returns the token + user data in the JSON response. HTTP-only cookies mean JavaScript cannot read the token — only the browser sends it automatically.

register(req, res)

1️⃣ Validates input using express-validator. 2️⃣ Blocks ADMIN_EMAIL from registering (reserved). 3️⃣ Checks for duplicate email. 4️⃣ Creates user (password auto-hashed by pre-save hook). 5️⃣ Sends welcome email via Brevo (in background). 6️⃣ Returns JWT + user data.

login(req, res)

1️⃣ Finds user by email (with .select('+password') to include the normally-hidden password hash). 2️⃣ Compares password with bcrypt. 3️⃣ Checks if banned → 403. 4️⃣ Checks maintenance mode (non-admins blocked) → 503. 5️⃣ If agency role → checks if organization is verified by admin → 403 if not. 6️⃣ Issues JWT.

registerOrg(req, res)

Registers a new agency organization. 1️⃣ Creates a User with role: 'agency'. 2️⃣ Uploads license document to Cloudinary. 3️⃣ Creates Organization document linked to user. 4️⃣ Sets verified: false (must wait for admin approval). Returns JWT but the agency cannot log in until an admin verifies them.

requestPasswordChangeCode(req, res)

Generates a random 6-digit code, stores it on the user with a 10-minute expiry, and emails it via Brevo.

verifyPasswordChangeCode(req, res)

Verifies the 6-digit code matches and hasn't expired. If valid, updates the password (which triggers bcrypt re-hashing via pre-save hook).

getLeaderboard(req, res)

Queries top 50 citizens sorted by XP descending. Aggregates report counts per user. Returns ranked leaderboard with avatar, XP, report count, and achievement count.

checkAchievements(req, res)

Evaluates all 8 achievements for the current user. Returns newly unlocked + full achievement list with unlock status.

8. auth.google.controller.js Google OAuth

controllers/auth.google.controller.js

googleLogin(req, res)

1️⃣ Receives Google accessToken from frontend. 2️⃣ Calls Google's https://www.googleapis.com/oauth2/v3/userinfo API to get verified user info (email, name, picture). 3️⃣ If user exists → checks ban status, updates avatar, issues JWT. 4️⃣ If new user → creates account with role: 'citizen', isVerified: true, and a random password (they'll use Google login, not password). 5️⃣ Returns JWT.

9. admin.controller.js Platform Admin

controllers/admin.controller.js (492 lines)

Full platform administration — stats, user management, organization verification, report assignment.

getStats(req, res) — Dashboard Analytics

Fires 15 parallel MongoDB queries using Promise.all() for maximum speed:

Total reports • Total users • Total organizations • Total communities • Reports grouped by status (aggregation) • Reports by month (12-month trend) • 10 most recent reports (with user info) • Reports by category • Reports by priority • 5 newest users • 5 pending (unverified) organizations • Critical open report count • Unverified org count • Pending review count • In-progress/assigned count.

assignReport(req, res) — 5-Channel Notification

Assigns a report to an organization. Triggers 5 separate notification channels:

1️⃣ Socket.IO event → real-time UI update for agency.
2️⃣ In-app notification → stored in Notification collection.
3️⃣ Email to agency → Brevo transactional email with report details.
4️⃣ Email to citizen → telling them which agency was assigned.
5️⃣ Browser push → to both agency and citizen devices.

banUser(req, res) / unbanUser(req, res)

Sets user status: 'banned' with reason, timestamp, and who banned them. Sends in-app notification + push notification. Admin accounts cannot be banned (safety check). Unbanning restores status: 'active' and clears ban metadata.

bulkBanUsers(req, res)

Bans multiple users at once using MongoDB updateMany(). Excludes admin accounts. Returns count of affected users.

verifyOrganization(req, res)

Admin approves an agency registration. Sets verified: true and status: 'Active'. Sends verification email + in-app notification + push notification to the agency owner.

deleteOrganization(req, res)

Removes an organization AND its linked user account. Also unassigns all reports that were assigned to this org (sets assignedTo: null).

deleteUser(req, res)

Deletes a user and ALL their reports and organization records. Cannot delete admin accounts (safety check).

12. ai.controller.js AI Intelligence

controllers/ai.controller.js (228 lines)

Gemini AI report analysis with keyword-based fallback engine.

analyzeReport(req, res) — Dual-Engine Analysis

Primary: Gemini AI — Sends a structured prompt asking for JSON with category, summary, severity, and suggested organization. Cleans response (strips markdown fences), parses JSON, validates against allowed values.

Fallback: localAnalysis() — If Gemini is unavailable/rate-limited, uses a keyword-matching engine with 55+ environmental keywords across 8 categories, 4 severity levels, and 6 organization types. Counts keyword matches and picks the highest-scoring option.

findDuplicates(report) — Jaccard Similarity

Queries reports with the same category created in the last 7 days. Tokenizes title+description into word sets. Computes Jaccard similarity (intersection/union of word sets). Reports with similarity > 30% are flagged as potential duplicates.

16. Logger Utility Utility

utils/logger.js

Centralized logging using Winston with 5 severity levels.

Winston Logger Configuration

5 log levels: error (0) → warn (1) → info (2) → http (3) → debug (4). Production only logs up to info; development logs everything including debug.

3 transports:
1️⃣ Console — colorized, human-readable output with timestamps.
2️⃣ error.log file — only errors, written to server/logs/error.log.
3️⃣ combined.log file — ALL messages, written to server/logs/combined.log.
